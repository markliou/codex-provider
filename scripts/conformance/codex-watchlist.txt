# Codex source files whose behavior the pool must match, read at the release
# pinned in upstream/Cargo.toml. `codex-conformance.sh diff <new-tag>` prints
# every change to these files between that release and a new one; each change
# must be read and either matched in the pool or recorded as not applying.
# A path that no longer exists fails the check: follow the rename and update
# this list rather than dropping the entry.
#
# Format: <direction> <path> <what the pool must match>
#   send    = what the pool puts on the wire
#   receive = how the pool reads what upstream sends back
#   policy  = what Codex does about it (retry, reconnect, give up)

send    codex-rs/codex-api/src/endpoint/responses.rs                 HTTP Responses request: path, headers, body, compression
send    codex-rs/codex-api/src/endpoint/responses_websocket.rs       WebSocket handshake headers and response.create messages
send    codex-rs/codex-api/src/requests/                             request body construction (headers, payload, prewarm)
send    codex-rs/codex-api/src/auth.rs                               credential and ChatGPT-Account-ID headers
send    codex-rs/codex-api/src/provider.rs                           base URLs, routing hint and per-provider headers
send    codex-rs/codex-api/src/common.rs                             shared request types (prompt_cache_key, client_metadata)
send    codex-rs/http-client/                                        HTTP client: TLS, HTTP/2, header order (the pool links it)
send    codex-rs/websocket-client/                                   WebSocket client (the pool links it)
receive codex-rs/codex-api/src/sse/responses.rs                      SSE event types, lifecycle and terminal events
receive codex-rs/codex-api/src/sse/responses_error.rs                error codes inside response.failed

receive codex-rs/codex-api/src/error.rs                              flex_unavailable and other shared error parsing
receive codex-rs/codex-api/src/rate_limits.rs                        codex.rate_limits event and rate-limit headers
receive codex-rs/codex-api/src/responses_headers.rs                  response headers Codex reads (turn state, model, reasoning)

send    codex-rs/backend-client/src/client.rs                       the pool's own backend calls: account check, headers

send    codex-rs/login/src/auth/default_client.rs                   default headers, user agent, client per route
send    codex-rs/login/src/device_code_auth.rs                      the sign-in prompt the pool parses
send    codex-rs/core/src/attestation.rs                            x-oai-attestation
policy  codex-rs/model-provider/src/provider.rs                     which providers get internal metadata (client gap)
policy  codex-rs/model-provider-info/src/lib.rs                     which base URLs count as the Codex backend (native endpoint)
